# Repo review, 2026-09-03 — findings and the work they imply

Transposed from GitHub issue #1 (`saul`, 2026-09-03). The issue is the record
of *what was found*; this file is the record of *what is being done about it*,
and it is the one that gets updated. Every finding keeps its original
identifier (`F1`…`F16`, `S1`…`S8`) so the issue and this file can be read
side by side.

The review was six parallel passes over the whole repo — engine core and the
script VM; the gameplay port; render and app; UI and the web tooling; the
Python side; docs, process and git — each reading its area in full, followed
by an independent re-check of everything marked confirmed. **No Ghidra and no
game directory were available to it**, so nothing in it is a claim about
fidelity to the exe. It is a claim about whether this repo is internally
consistent, correct, and shaped to absorb the next thirty classes.

That limitation matters for how the findings are treated here. A review that
could not read `Hod2.exe` can tell us that `FUN_0044AD60` is transcribed twice
with different bodies (F3); it cannot tell us which body is right. Findings
that turn on the binary are marked below and are `/gameplay-port` jobs, not
edits.

### Gameplay correctness

**F1 — the motion cursor skips play-frames 7, 15, 31, 507.** `game/motion.ts`
accumulates `obj.clock += dt` with `dt = 1/60`; `game/tables.ts` derives
`cursor = Math.floor(clock * fps * 2)`. Repeated float addition of 1/60 does
not land on multiples of 1/60:

```
tick 6: clock=0.09999999999999999 → floor(*60)=5    duplicate
tick 8: clock=0.13333333333333333 → floor(*60)=8    7 never observed
```

Reproduced in node: duplicates at ticks 6, 12, 24, 85; skips at 8, 16, 32, 508
— which frame is lost shifts with the clip's start phase. Sixteen call sites
test the cursor with `===`, on the correct reasoning that `>=` double-fires
across the `% (len + 1)` wrap: `class30/target.ts` (eight),
`class30/scripted.ts` (three), `class30/emerge.ts`, `class30/entrance.ts`,
`class30/fall.ts`, `class24/index.ts`, `class10/index.ts`, `class25/index.ts`.
**An authored cue of 7, 15 or 31 never fires and the actor parks.** That is the
shape of every item in `PLAYER_HANGS.md`.

The exe's `obj+0x19C` is an integer, and the architecture doc's "whole ticks,
never a fraction" rule is honoured by `G.g_frame` and not by the motion clock.
Three frame-unit conventions coexist: `MotionPlayFrame` in half-frames,
`class25.AtLastMotionFrame` in authored frames, `class31/arc.ts`'s
`ActorClipFrame` in seconds × 60. The `[diverges]` on the `struck` latch
(`actor.ts`) and on `g_cam_path_frame_prev` (`globals.ts`) both compensate for
this, and the latter's stated reason — "runs on real elapsed time" — is no
longer true.

*Fix (S1):* `clock` becomes an integer tick count; `MotionPlayFrame` becomes
`ticks % (len + 1)`; seconds are derived only at draw. Test: play a clip from
every start phase and assert each play-frame is observed exactly once. Removes
two divergences.

**F2 — a seek does not reseed the world RNG.** `app/main.ts`'s `seekTo` resets
`G`, the containers, the session scope and the walker; only `stage_load.ts`
calls `p.rng.reseed`. The port's ~35 draw sites consume `ctx.rng`, so two seeks
to one address from different histories replay the script identically and then
diverge on the first `rng.int()`. `test/state.test.ts`'s `seekInto` has the
same omission, so the strictest test in the repo would not catch it even with a
bundle. *Fix: one line in each.*

**F3 — `FUN_0044AD60` (`ThrowerLeave`) is transcribed twice with different
bodies.** `class31/death.ts` exports one — retires from the alive and present
counts, releases the permit — and `class31/scripted.ts` has a private one that
only releases the permit, called from its own state. "One exe function, one TS
function" is the port's first rule, and the counts diverge depending on which
exit a thrower takes. `verify_port.py` builds citations per file and never
checks for one address defined in two.

**Which body is `FUN_0044AD60` is a question for the binary**, not a merge:
resolving this is a `/gameplay-port` job that re-reads the routine and the
state that calls it.

*Resolved.* The exe's body is
`ThrowerRetireFromAliveCount` → `ThrowerRetireFromPresentCount` →
`ThrowerReleaseAttackPermit` → free `g_enemy_slots[obj+0x120]` →
`obj+0x34 &= ~1` → `ActorDespawn`, and its only two callers are
`ThrowerStrikeConnect` (`FUN_0044CE60`) and `ThrowerStateGrabPlayer`
(`FUN_0044EF90`). `death.ts` had it nearly right and was missing the slot
drop and the despawn; `scripted.ts`'s private copy was wrong, and it was the
one the grab called. **This was a live hang**: a thrower that finished its
grab-and-throw left both counts one too high for the rest of the stage, so
any later `wait_enemies_alive` could never open. Bit 0 of `obj+0x34` remains
`[open]` — nothing in the ported call graph reads or writes it.

**F5 — counters can go negative.** `CountEnemyZombieIn` (`combat/counts.ts`)
skips initial state 0x1F and char type 9, but the release paths
(`class30/walk_distance.ts`, `director.ts`) release unconditionally, latched
only on `flags38`. A never-counted zombie swept by a region unload or
`ActorKillAll` takes `g_enemies_alive` below zero, and every later
`wait_enemies_alive` opens early. Related: `ReleaseAttackSlot`
(`combat/permits.ts`) frees `g_attack_permits[i]` without checking the slot
still belongs to `obj.at`, and the director's dead-sweep calls it every frame
on every dead actor.

**F6 — `RankEnemiesByDistance` writes `rank = -1, queueRank = 0` onto every
non-zombie actor every frame** (`combat/rank.ts`) — a class-0x30 routine
writing class-agnostic offsets onto other classes' structs. Harmless today
because nothing else reads them; exactly the polymorphic-field trap `CLAUDE.md`
warns about, and a type error under S3.

### The checks that cannot fire

This is the largest group, and the most serious: **a rule that reads `ok` over
a hole it cannot see is worse than no rule**, because it is also an argument
against looking.

**F7 — `verify_port.py`'s coverage figure is inflated.** It counts the
denominator inside five address ranges and the numerator over every ported
definition anywhere, including opcode handlers and classes 0x10/0x24/0x25/0x41
that fall outside those ranges. Same ranges applied to both: 148 of 234, not
78%. This is the number the architecture doc calls "the most honest progress
metric this project could have".

**F8 — two version constants that have never moved.** `SNAPSHOT_VERSION` and
`BUNDLE_FORMAT` have both been `1` since they were introduced, across 28
commits to `globals.ts`, every `saveState` shape change, and 23 commits to
`bundle.py` that added `coli`, `civilians`, `humanoids` and `set_pieces` and
renumbered `game_mode`. Both checks exist and neither has ever been able to
fire. `RestoreGameGlobals` is `Object.assign(G, saved)`, so a missing key keeps
the live value; `World.load` `continue`s past a missing slice despite its
docstring promising to refuse outright. A stale bundle silently loses collision
and civilians.

**F9 — `no-engine-writes-in-render` only matches `G.…=`.**
`render/characters.ts` and `characters/gore.ts` write `inst.a.visible`,
`inst.a.lookAt` and `inst.a.boneSlot` — actor fields, from `render/`.
`a.visible` gates alive-counting, and a comment in that file records that a
previous version of the line broke every wait gate. The rule reports `ok`.
Also: `render-drives-the-port`'s import regex is depth-1 (`../game/`), so a
value import from `render/characters/*.ts` is invisible; `layers-are-systems`
only scans files whose parent is `render/`; the DOM regex misses `performance`
and `Date`.

**F10 — three tests exit 0 having asserted nothing.** `seek`, `state` and
`camera` print "no bundle" and pass. Their bundle path is hard-coded to
`$HOME/hotd2-decomp/extract/player`, as it is in ten tools under `web/tools/`,
while `vite.config.ts` resolves `../extract/player` — so on a checkout at any
other path they can never find a bundle even when one is built. **On this
checkout they do run**, which is why nobody noticed. Separately, every
`npm run test:*` passes `--experimental-strip-types`, which `run_test.mjs`
makes redundant (it bundles with esbuild first) and which node < 22.6 rejects
outright with `bad option` — so `CLAUDE.md`'s check block does not run as
written on node 20, and `package.json` declares no `engines`.

**F11 — `manifest.csv` pins the rotted install.** Generated 2026-08-29, never
regenerated after the 2026-08-31 finding that four `cam/` files and
`st1evtbl.bin` were damaged; row 9 is the damaged `cp_st1.bin`. The lesson is
in `CLAUDE.md` under "things that have cost this project real time"; the
artefact contradicts it, and nothing checks an install against the manifest.
`exetab.py` reads ~70 hard virtual addresses out of `Hod2.exe` with no hash
gate, so a different build produces plausible garbage.

**F12 — the escalation procedure points at a deleted section.** `CLAUDE.md`
and the `gameplay-port` skill (five places) send a blocked agent to the "Order
of work" table in `PLAYER_ARCHITECTURE.md`, and `verify_layers.py` prints
`held (step 11)` / `(step 5)` against it. **That table no longer exists.** The
most important process rule in the repo — *never add a violation to get work
done; here is where to go instead* — cannot be followed to the letter.

### Resource lifetime (render)

**F13 — unowned GPU caches keyed on volatile text.** `render/debug.ts`'s
`LABELS` is a module-level `Map<string, CanvasTexture>` keyed on label text,
and the text contains `d=${d.toFixed(0)}` — so every metre an actor moves
mints a texture that is never freed. `render/props.ts` has the same unowned
cache. `SpawnLayer` already fixed this pattern and the other two did not
follow. Also unowned: `StageScene.dispose` skips textures, `RailLayer` is never
disposed, `ImpactSprites` lives for the page.

**F14 — late clones lose the fog shader.** `Material.clone()` in `backdrop.ts`
and `rain.ts` runs after `sceneFog.prepare`, and three's `Material.copy` does
not copy `onBeforeCompile` — so dome and rain get planar fog while the stage
gets radial. `Backdrop` spins on wall-clock × 60 rather than ticks.
`Shooting.pickOne` and `BreakableLayer.shake` use `Math.random` — render-only,
so not a layer violation, but it breaks driven-run reproducibility. Stage load
is not re-entrant: two fire-and-forget calls in `commands.ts` mean a second
load disposes the scope the first is building into.

### UI

**F15.** `Transport.tsx` ends a scrub on `onMouseUp` only, so touch or pen
leaves `scrubbing = true`. `isTyping` omits `BUTTON`, so Space on a focused
transport button toggles play twice — `shot.mjs` blurs first as a workaround,
and the workaround is the evidence. `Minimap.tsx` seeks to `step: 0`, the
checkpoint step ordinary play never enters. `usePersisted` is
read-all/spread/write under one key, so the last writer wins across tabs.
`scopes: appScope.snapshot()` rebuilds the whole scope tree every frame whether
or not the panel is open; it belongs behind `wants("scopes")` like the other
expensive slices.

### Python

**F16.** Fifteen `except Exception: return {}` / `pass` sites across
`bundle.py`, `props.py`, `characters.py`, `rigs.py`, `stage.py` and
`export_level.py` turn a parser regression into a valid bundle with zero
characters and no message — the exact "silent exporter regression" `PLAN.md`
P6 says nothing catches. `ExportAnnotations.java` sorts both TSVs and drops the
body comments, while `CLAUDE.md` says never re-sort and `PLAN.md` says run it
after every session. `docs/formats/combat.md` cites `FUN_004073B0` as
`SpawnImpactSprite` where the TSV says `SpriteEffectSlotRange`; docs↔TSV is the
unchecked edge, with 52 more bare `FUN_` citations in docs that are not in the
TSV at all.

## Design assessment

### What is good, and should not be touched

* **The layer split and its checker.** Down-only dependencies, `render` owns
  nothing, `ui` reads one projection. Twelve rules, ten at zero, two ratchets
  with written baselines. The refusal to add a suppression comment is right.
* **The port convention.** Name and address in the doc comment, `G` as the data
  segment, offsets on the struct, enums for closed sets, `[diverges]` tagged and
  counted. It has made the code greppable in both directions and it visibly
  changed the bug rate after it was adopted.
* **Snapshot as proof.** `world.save()` through `structuredClone`, with
  `test:port`'s JSON round-trip and same-seed determinism. "If it can't be
  saved, state is hiding" has found real bugs.
* **The fixed-tick loop** with spread-not-dropped debt, the sleep/wake
  chokepoints, and `pacing.mjs` proving it on the real page.
* **Scopes** — a LIFO disposal tree, `resync` as the single rebuild path for
  both seek and load, and `test:scope` written to fail deliberately once.
* **The projection/command seam** — `share()` for identity stability, per-slice
  subscription, demand by mounting, six error boundaries, two AST rules in
  `verify_ui.mjs`. It is holding: no panel smuggles engine types.
* **`hod2lib`** is a genuine library with a clean DAG, `pathlib` throughout,
  sorted sets before output, byte-deterministic stage files.
* **Commit hygiene** — 260 of 260 conventional subjects, docs updated in the
  same commit as the shape change.

### Where the design is weaker than the doc says

1. **The checks measure proxies that have drifted from the property.** F7–F10
   are all this, and four rules currently cannot fire.
2. **Two versions that never move** (F8). A version check whose constant nobody
   bumps is documentation, not a check. Nothing ties "the `saveState` key list
   changed" to a bump.
3. **The motion clock is a second clock** (F1). "One clock, whole ticks" is
   true of the loop and false of the actor, and every `===` cue test is a
   latent hang.
4. **`Actor` is 130 fields with ~25 offset aliases** — `arcPhase`/`pathOffset`
   at +0x1360; `slideTimer`/`hitMode`/`throwDelay`/`arcFrames`/`pathDelay` all
   at +0x1330. Five TS names for one exe word is five places that can disagree
   after a snapshot, with no type-level protection. `class10` already solves
   this with `civ: CivilianState | null` as a per-class sub-block.
5. **`walker.ts` still holds a hidden switch.** Ops and waits register cleanly,
   but `applyQueueEvent` is ~140 lines of `if (op.action === …)` over string
   literals — the exact shape `ops/` was built to remove, and where the ring
   and cam accounting bugs have historically lived. `seek.ts`, `waits/` and
   `state/` are already out; the doc's "not split out yet" is stale.
6. **`main.ts` has grown past its defence by exactly one seam**: the pacer is
   the other half of `loop.ts` and has a crisp interface. The rest of the growth
   is the composition root and should stay.
7. **The Python↔TS bundle contract is enforced by eyeballs.** Forty TS
   interfaces hand-mirror `bundle.py`'s dicts, `getJson<T>` is a bare cast, and
   the one integer that could catch drift has never moved. Gameplay
   *immediates* read from `.text` are baked into the bundle, so a gameplay
   constant lives in Python with its citation while the TS that uses it has
   none and `verify_port.py` cannot see it. **Rule to adopt: tables from
   `.rdata` go in the bundle; immediates from `.text` go in `game/` with their
   citation.**
8. **`core/system.ts` imports `Walker`** — the framework names the one machine
   it hosts. `ctx.frame` and `G.g_frame` are two owners of one fact, copied
   every tick.
9. **Documentation weight.** 22k lines of markdown against 52k of code, with
   `session-log.md` at 9,083 lines touched in half of all commits. Three
   different "start here" pointers give three different orders. `README.md`
   still describes the project as "asset + render pipeline, **not** gameplay".

## Structural changes

In order of leverage. Each is a shape change, not a line-count exercise.

* **S1 — integer motion clock** (F1). One field changes meaning; sixteen `===`
  sites become correct by construction; three unit conventions collapse to one
  `motion.ts` API; ~10 per-class `frameOf`/`atLastFrame` helpers disappear; two
  `[diverges]` go.
* **S2 — input intent on `G`, closing `render-drives-the-port`.** The
  architecture doc owes this ratchet a step; this is its shape.
  `G.g_shot_requests: {player, frame, ray}[]`, pushed by `Shooting.fire`;
  `game/combat/shot.ts` gains `ProcessShotRequests` at the head of `GameUpdate`,
  asking a new `host.pickShot(ray)` for `{at, bone, point} | {propId} | null`
  and dispatching to `MarkActorShot` / `BreakablePropTakeShot` / `ResolveHit` +
  `ScoreAddForPlayer`. Head-combo moves onto `G.g_head_combo_bonus`, already
  declared and today shadowed by a second copy in `shooting.ts`. The camera
  seat's Hermite evaluation ports from `render/campath.ts` to
  `game/camera/curve.ts` over `Vec3`. Result: the ratchet reaches 0 and flips to
  `error` — **and the shot queue is an input replay log for free**, which is the
  regression harness the plan has wanted since day one. ~1 week.
* **S3 — discriminated-union `Actor` tail.** Keep the shared head and move the
  per-class tail behind `cls`. Plain objects, still cloneable; the 25 aliases
  vanish; F6 becomes a type error. ~2 days, mechanical.
* **S4 — self-registering class modules and `ClassFrame` everywhere.** Three
  files carry comments about ESM cycles resolving tables to `undefined`. Have
  each class module call `registerClass`, add `onDeadSweep?` to the handler, and
  split `class10/index.ts` (1,465 lines) along the exe's own boundaries as
  class30/31 already are. ~2 days.
* **S5 — walker: extract `state/shutter.ts` and `state/camera_action.ts`**, the
  latter as an action registry. Delete vestigial state (`Walker.rng`/`seed`,
  saved and restored and never drawn from; `WalkerHost.loadRegion` /
  `releaseCamera` no-ops). Assert no duplicate opcode. ~2 days.
* **S6 — versions that move, and a contract that is checked.** Bump both
  constants; `World.load` refuses when a `load`-capable system has no slice; a
  test asserts `saveState()`'s keys equal `loadState`'s list; `manifest.json`
  carries a schema hash of `web/src/bundle/*.ts` computed at export and compared
  at load. ~1 day.
* **S7 — `app/pacer.ts`** out of `main.ts`; `hudInputs` to `projection/hud.ts`.
  ~1 day.
* **S8 — `hod2lib/characters.py` split**, then apply the `.rdata`/`.text` rule
  above. ~1 day.

## Opportunity on the table

Things the design already makes cheap and nobody has done:

* **Snapshot ring and rewind.** `world.save()` is plain JSON and `saved` is one
  slot. A 60-deep ring and a `rewind` command is under 50 lines, and it directly
  attacks the stated pain of only being able to test something after the second
  zombie dies.
* **A headless determinism assertion in the check block.** `determinism.mjs`
  and `playthrough.mjs` exist, need Chrome, and are wired to nothing.
* **A bundle-free fixture.** `port.test.ts` already hand-writes a
  `ScriptJson`-shaped scene. A `test/fixtures/mini_stage.script.json` with 5–6
  blocks covering every wait kind, plus a 2-frame `CamJson`, makes
  `seek`/`state`/`camera` run on every machine and covers F2 and F4 directly.
* **A golden hash suite in `tests/`**, keyed on the EXE hash, comparing
  per-file SHA-256 of an export to a temp dir, skipping when assets are absent.
  This is `PLAN.md` P6 and it is a day. **No asset is committed.**
* **Whole-`G` snapshot digest** and save/load every N frames in `test:port`;
  today's digest is nine actor fields, and this is the test that would have
  caught `lookAt` staleness.
* **Screen-space actor positions in the projection** — `playthrough.mjs` sprays
  a grid because it cannot aim.
* **`docs/STATUS.md` generated from the tools**, so the architecture doc can
  stop carrying numbers that go stale in a day.

## What not to do

The review was explicit about these, and they are as load-bearing as the
findings:

* **Do not extract `vm.ts` from the walker** — the machine is the clean part.
* **Do not add ESLint** — the architecture doc's argument still holds; the two
  AST rules are enough and `verify_ui.mjs` must not grow.
* **Do not add interpolation to the render loop** — correctly deferred.
* **Do not split `main.ts` by line count** — only the pacer has a seam.
* **Do not raise either ratchet.** Phase 3 lowers one to zero.
